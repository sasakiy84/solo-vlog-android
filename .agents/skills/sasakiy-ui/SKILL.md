# Sasakiy UI

UI を実装・修正・レビューするときに使う。まずリポジトリの `AGENTS.md`、既存画面、デザインシステム、関連テストを確認する。

## 重要事項
- 不要なセカンダリラベルや説明を避けて、レイアウトで説明させる

## レイアウト

- 要素同士が重なっていないことを確認する。
- 機能として関連する要素は近接させ、関連のない要素は適度に離す。
- 横に並ぶ要素は、枠線も含めて上下の端を揃え、同じ高さにする。
- 縦に並ぶ要素は、枠線も含めて左右の端を揃え、同じ幅にする。
- 同じ意味の要素には同じ余白を使う。
- 想定したスペースに収まらない場合は、スペース自体を広げる必要があるか、無駄な情報が混ざっていないかを確認する。

## 色

- ページ全体のトーンを決める色は 1〜2 色、補助的な色は 1〜2 色に抑える。
- `border-left` だけで色を変えてレイアウトを分かりやすくする設計は避ける。
- 色だけに意味を持たせず、テキスト、アイコン、配置、状態表現も併用する。

## アクセシビリティと操作

- 連打や二重送信を防ぎ、更新ロジックの誤適用を防ぐ。
- Tab、Enter、Escape、Ctrl/Cmd+Z などのキーボード操作を主経路として設計する。
- フォーカス状態、disabled 状態、loading 状態、エラー状態を確認する。
- アニメーションは意味がある場面だけ、短く使う。
- パネルを分ける場合、原則としてスクロールも分ける。意味的な関連性がある場合のみスクロールを同期させる。

## 検証

- UI 要素を変更した場合は、実際の画面の表示状態を確認する。
- 画面幅、長いテキスト、空状態、エラー状態、loading 状態で破綻しないか確認する。
- テキストがボタンやカード内からはみ出さないか確認する。
- UI レビューでは、見た目の好みより、操作不能、誤操作、視認性低下、情報の欠落を優先して指摘する。
